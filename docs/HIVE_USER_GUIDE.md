# Hive — мультиагентная подсистема M7

Hive запускает несколько моделей с разными ролями на одной задаче и синтезирует их ответы. Используется как вход для фазы SOLUTION при решениях с высокой ценой ошибки; цикл M7 не заменяет.

Сведения ниже соответствуют коду `src/hive/` (версия пакета 3.18.0). Требуются `OPENAI_API_KEY` и `ANTHROPIC_API_KEY`. Каждый вызов стоит денег: стоимость считается по токенам и выводится в отчёте.

## Тулы

| Тул | Назначение |
|---|---|
| `mcp_m7_hive_coordinator` | запуск разбора задачи |
| `mcp_m7_hive_history` | список (`list`, с фильтром `query`) и загрузка (`load`, параметр `filename`) прошлых отчётов из `docs/hive/` |

## Параметры `mcp_m7_hive_coordinator`

| Параметр | Тип | По умолчанию | Назначение |
|---|---|---|---|
| `task` | string | — | описание задачи |
| `mode` | `dynamic` \| `fixed` \| `planned` | `dynamic` | режим формирования команды (ниже) |
| `agents` | массив из `research`, `implementation`, `architecture`, `security`, `testing`, `performance`, `techsafety` | — | состав команды; **учитывается только в `mode: "fixed"`** |
| `debate_mode` | boolean | `true` | дебаты между агентами при расхождении предложений |
| `max_rounds` | number | `3` | предел раундов дебатов |
| `priority` | `speed` \| `quality` \| `consensus` | `quality` | `speed` уменьшает бюджет токенов на агента вдвое относительно остальных |
| `plannerOptions` | объект | — | только для `planned`: `maxSubtasks` (8), `auctionTimeoutMs` (5000), `gatekeepers` (`style`, `arch`, `security`, `test`), `parallelAuctions` (true) |

## Режимы

**`dynamic`** (по умолчанию). Сервер сам формирует команду экспертов под задачу, подбирает модель для каждой роли по данным бенчмарков (`src/hive/intelligence/modelSelector.ts`, базовые данные LiveBench в `benchmarkData.ts`) и корректирует выбор по накопленным результатам (`selfLearning.ts`, файл `.m7/hive-adjustments.json`). Параметр `agents` игнорируется. Перед запуском в контекст агентов добавляются релевантные записи из памяти проекта.

**`fixed`.** Команда задаётся параметром `agents`. Роли и модели по умолчанию (`src/hive/api/apiManager.ts`; могут быть обновлены при обнаружении доступных моделей):

| Роль | Провайдер / модель | Специализация |
|---|---|---|
| `research` | Anthropic `claude-opus-4-6` | исследование, анализ, документация |
| `implementation` | OpenAI `gpt-5.5` | код, оптимизация, отладка |
| `architecture` | OpenAI `gpt-5.5` | проектирование системы |
| `security` | Anthropic `claude-opus-4-6` | аудит безопасности, уязвимости |
| `testing` | OpenAI `gpt-5.2` | генерация тестов, граничные случаи |
| `performance` | Anthropic `claude-sonnet-4-6` | производительность, метрики |
| `techsafety` | Anthropic `claude-opus-4-6` | оценка технологий и рисков (связана с TSI) |

Если `agents` не указан, команда подбирается автоматически.

**`planned`.** Задача декомпозируется планировщиком на подзадачи, подзадачи распределяются между агентами через аукцион (Contract Net Protocol), результаты проверяются выбранными gatekeepers. Предназначен для задач, которые невозможно разобрать одним ответом.

## Дебаты

При `debate_mode: true` и более чем одном предложении агенты обмениваются критикой до `max_rounds` раундов; затем синтезатор (`claude-opus-4-6`) формирует итог с разделами «консенсус» и «разногласия». При одном предложении дебаты не проводятся.

## Результат

Тул возвращает текст: краткую сводку (число экспертов, стоимость, время) и ссылку на полный отчёт, сохранённый в `docs/hive/<YYYY-MM-DD>_<HHMM>_<slug>.md`. Полный отчёт содержит предложения агентов, ход дебатов, синтез, стоимость по агентам. Объектов с полями `total_cost`, `agents_used` и т. п. тул не возвращает; данные берутся из отчёта.

## Примеры

```json
// разбор архитектурного решения, команда формируется сервером
{ "task": "Спроектировать слой кэширования для API поиска: инвалидация, TTL, согласованность", "mode": "dynamic", "priority": "quality" }

// ревью безопасности фиксированной командой без дебатов
{ "task": "Проверить модуль аутентификации на уязвимости", "mode": "fixed", "agents": ["security", "architecture"], "debate_mode": false }

// декомпозиция большой задачи с проверкой результатов
{ "task": "Перевести слой хранения с JSON-файлов на SQLite", "mode": "planned", "plannerOptions": { "maxSubtasks": 6, "gatekeepers": ["arch", "test"] } }

// история
{ "action": "list", "query": "cache" }
{ "action": "load", "filename": "2026-02-07_1423_caching-layer.md" }
```

## Стоимость

Стоимость считается по фактическим токенам и тарифам, зашитым в `dynamicOrchestrator.ts`; выводится в сводке и отчёте. Снижают стоимость: `priority: "speed"`, `debate_mode: false`, малое `max_rounds`, фиксированная команда из одной-двух ролей. Порядок величины для одного запуска с тремя агентами и дебатами в три раунда — десятки центов; точная сумма зависит от длины задачи и контекста.

## Интеграция с циклом

Типичное место — между DISCOVERY и SOLUTION: артефакт DISCOVERY передаётся в `task` вместе с вопросом, итог синтеза используется при составлении `SOLUTION_PLAN.md`. Решение, принятое по итогам Hive, сохраняется через `mcp_m7_memory store_pattern` с указанием рассмотренных альтернатив.

## Ограничения

- Без ключей обоих провайдеров сервер не стартует (см. README).
- Hive не выполняет код. В режимах `dynamic` и `fixed` контекст агентов — текст задачи и записи памяти проекта; в `planned` дополнительно подтягиваются фрагменты релевантных файлов, найденные ripgrep (по умолчанию до 10 файлов, около 4000 токенов; `src/hive/context/`). Полное чтение репозитория не выполняется — результаты DISCOVERY нужно передавать в `task` явно.
- Качество синтеза зависит от формулировки: задача с явными ограничениями и ожидаемым форматом ответа даёт более проверяемый результат.
