# Принципы методологии M7

Документ формулирует принципы, лежащие в основе M7, указывает, какую ошибку агента каждый из них предотвращает, и где принцип реализован в сервере. Обоснование на материале практики — `docs/M7_WHY_FULL_CYCLE.md`; процесс — `Methodology/IDEAL_METHODOLOGY.md`; рабочие правила — `M7-GUIDE.md`.

## 1. Исследование до реализации

**Формулировка.** Изменение кода допускается только после того, как зафиксированы: переформулированная задача и критерии успеха (INTAKE), прочитанный релевантный код и найденные причины (DISCOVERY), описание затронутой архитектуры (ARCHITECTURE).

**Предотвращаемая ошибка.** Иллюзия знакомства: вывод о причине по узнаваемому симптому без чтения кода. Преждевременная сходимость: принятие первой гипотезы как единственной.

**Реализация.** Фазы `intake`, `discovery`, `architecture` в `src/core/orchestrator/cycleOrchestrator.ts`; инструкции этих фаз запрещают правку файлов. Маршрутизатор (`src/core/router.ts`) при флаге `heavy_first_routing` (включён по умолчанию) назначает полный цикл любой задаче; облегчённого маршрута с пропуском фаз нет.

## 2. Явный анализ последствий

**Формулировка.** До реализации перечисляются затрагиваемые компоненты, возможные регрессии, граничные случаи и радиус изменений; план прогоняется по сценариям без правки кода.

**Предотвращаемая ошибка.** Регрессия в коде, который агент не читал; скрытое состояние и порядок событий, не учтённые в плане.

**Реализация.** Фазы `impact` и `simulation`; тул `mcp_m7_impact` (`src/core/tools/critical/impact.ts`) для анализа по списку файлов; граф зависимостей `mcp_m7_knowledge_graph`.

## 3. Блокировка по критическим рискам

**Формулировка.** Риск классифицируется как critical, major или minor. Неустранённый critical-риск останавливает продвижение; план и анализ влияния перевыпускаются новой версией до тех пор, пока critical-рисков не останется. Major требует явного подтверждения; minor фиксируется.

**Предотвращаемая ошибка.** Накопление известных, но отложенных рисков, которые проявляются одновременно на этапе реализации.

**Реализация.** `src/core/router.ts` — задача не может продолжаться при наличии рисков с `severity: 'critical'` без поля `mitigation`; файл `RISK_MITIGATION.md` в структуре задачи (`src/core/tools/createStructure.ts`).

## 4. Внешний контроль соблюдения протокола

**Формулировка.** Соблюдение последовательности фаз обеспечивается сервером, а не инструкцией в контексте модели. Каждая инструкция фазы содержит одноразовый идентификатор; ответ на ворота без этого идентификатора отклоняется. После заданного числа вызовов инструментов в одной фазе сводка правил повторно вставляется в ответ.

**Предотвращаемая ошибка.** Деградация соблюдения правил в длинном сеансе: инструкция, данная в начале, вытесняется из внимания модели.

**Реализация.** `generateGateInstructionId` / `validateGateInstructionId` и `ruleReinjection.ts` в `src/core/orchestrator/`; порог — `M7_RULE_REINJECTION_THRESHOLD` или `cycle.rule_reinjection_threshold` в `config/m7-config.yaml`.

## 5. Персистентная память с явным статусом знания

**Формулировка.** Знание о проекте хранится между сеансами на пяти уровнях (L0 surface, L1 working, L2 longterm, L3 conceptual, L4 project) с уверенностью, которая убывает со временем и повышается при подтверждении. Для каждого утверждения о проекте различается статус: известно, предположено, устарело, неизвестно, подтверждено человеком.

**Предотвращаемая ошибка.** Повторное открытие того же решения в каждом новом чате; действие на основании устаревшего или непроверенного предположения, неотличимого от факта.

**Реализация.** `src/memory/memorySystem.ts` (уровни, уверенность, продвижение), `src/memory/fogBoundary.ts` («туман войны» — что известно и что нет), эпистемический статус в ответах `mcp_m7_memory`; на диске — `.m7/memory/`.

## 6. Доказательность диагноза

**Формулировка.** Утверждение о причине дефекта допускается только вместе с доказательством: строкой кода, записью лога, воспроизведением. Причина ищется в коде; окружение (кэш, сеть, браузер) рассматривается после исключения кода. Поиск не останавливается на первой причине.

**Предотвращаемая ошибка.** Диагноз по правдоподобию; «попробуйте очистить кэш» как замена анализа; пропуск второй независимой причины.

**Реализация.** Критерии ворот фазы DISCOVERY; правила 2–3 в `Methodology/CURSOR_METHODOLOGY_RULES.md`; тул `mcp_m7_repentance` для фиксации нарушений.

## 7. Проверка существования и актуальности

**Формулировка.** Любая сущность, не показанная в контексте явно (файл, функция, параметр тула, API библиотеки), проверяется поиском по коду или по актуальной документации до использования.

**Предотвращаемая ошибка.** Галлюцинация несуществующих функций, импортов и параметров; использование API той версии библиотеки, которой нет в проекте.

**Реализация.** `Methodology/ANTI_HALLUCINATION_CHECKLIST.md`; интеграция Context7 для документации; TSI (`src/tsi/`) — пакеты известных проблем стека; `mcp_m7_contracts` — проверка дубликатов перед созданием функции.

## 8. Точечные изменения и защита от самоуничтожения

**Формулировка.** Изменяются только строки, требуемые задачей. Код, написанный агентом в текущем сеансе, не признаётся дефектным без обращения к истории версий и подтверждения пользователя.

**Предотвращаемая ошибка.** Переписывание файла ради малой правки с утратой несвязанного кода; цикл «написал → назвал багом → удалил → написал заново».

**Реализация.** Разделы 7–8 `Methodology/CURSOR_METHODOLOGY_RULES.md`; `mcp_m7_scope` — бюджет файлов и строк на задачу.

## 9. Коллективный разбор сложных решений

**Формулировка.** Для архитектурных решений допускается параллельный разбор несколькими специализированными моделями с последующим синтезом; результат — вход для фазы SOLUTION, а не замена цикла.

**Предотвращаемая ошибка.** Единственная точка зрения на решение с высокой ценой ошибки.

**Реализация.** `src/hive/` — семь агентов (research, implementation, architecture, security, testing, performance, techsafety), режимы dynamic / fixed / planned, дебаты с ограничением раундов; см. `docs/HIVE_USER_GUIDE.md`.

## 10. Фиксация результата

**Формулировка.** Завершённая задача оставляет след: артефакты фаз, запись в реестре циклов, сохранённый паттерн в памяти, обновлённые справочные документы проекта. Отчёт содержит измеримые факты, а не оценки.

**Предотвращаемая ошибка.** Потеря уроков между сеансами; отчёты без проверяемого содержания.

**Реализация.** `m7-cycles/<task>/`, `CYCLE_REGISTRY.md`, `mcp_m7_memory store_pattern`; побочная запись соглашений в `CODING_STANDARDS.md` и `MASTER_REFERENCE.md` (`src/core/tools/unified/memoryTool.ts`).
